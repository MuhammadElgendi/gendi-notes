# Google Cloud Storage

> إزيك يا صاحبي! الملف ده معمول عشان يشرحلك كل حاجة عن خدمات التخزين في جوجل كلاود بالمصري، كده على الماشي. هنتكلم عن التخزين من نوع أوبجكت، وبلوك، وفايل، وكمان إزاي تتحكم في الوصول، وإيه الأدوات اللي بتستخدمها، وإزاي تختار الخدمة اللي على مزاجك.

## What is it?

Cloud Storage هو Object Storage مُدار في Google Cloud. الداتا بتتخزن كـ **objects** جوه **buckets**، بينما خدمات تانية بتوفر block أو file storage.

💬شرح

ببساطة: لو عندك ملفات وعايز تخزنها كـ objects استخدم Cloud Storage. لو محتاج disk للـ VM استخدم Block Storage. ولو محتاج shared filesystem استخدم File Storage. يعني بيخزّن الداتا على شكل **أوبجكت** (أي ملف بأي صيغة، ومش بيتغير بعد ما ترفعه) جوه حاجة اسمها **باكِت** (Bucket). كل باكِت بيبقى مربوط بمشروع، والمشروع نفسه تابع لمنظمة.

### Resource hierarchy

```text
Organization (المنظمة)
 └── Project (المشروع)
      └── Bucket (الباكِت)
           ├── Object (الأوبجكت - مثلاً: puppy.png)
           ├── Folder (الفولدر - لو فيه هيراركية)
           └── Managed Folder (فولدر مُدار - للتحكم في الصلاحيات)
````

✓The key distinction

Bucket هو الحاوية، Object هو الداتا نفسها، والـ Project هو اللي الباكِت تابع له.

### Core concepts

| **المصطلح**                      | **الشرح بالمصري**                                                                        |
| :------------------------------- | :--------------------------------------------------------------------------------------- |
| **Object (أوبجكت)**              | أي ملف ترفعه على التخزين، مبيتغيرش بعد الرفع، وكل باكِت بيشيل عدد ملهوش آخر منه.         |
| **Bucket (باكِت)**               | الحاوية اللي بتشيل الأوبجكتس. كل مشروع ممكن يكون فيه أكتر من باكِت.                      |
| **Folder (فولدر)**               | بيظهر في الباكِتس اللي فيها هيراركية، وبيخليك تعمل شجرة فولدرات حقيقية وتغيّر الأسماء.   |
| **Managed Folder (فولدر مُدار)** | بيخليك تدي صلاحيات زيادة عن اللي موجودة في الباكِت نفسه، بس مبيعملش شجرة فولدرات حقيقية. |

باكِتس التخزين دي هي أساس الدنيا كلها في جوجل كلاود، وبتتوصل بخدمات زي AI Hypercomputer وVertex AI وGoogle Kubernetes Engine.

## Storage classes

Storage Class هي خاصية للأوبجكت بتأثر على التكلفة والتوفر ورسوم الاسترجاع.

💬شرح

يعني نفس Cloud Storage، لكنك بتختار class مختلف حسب قد إيه الداتا بتتقرأ. لما تعمل باكِت، بتحدد فئة افتراضية، وكل الأوبجكتس بتاخدها إلا لو غيّرتها بنفسك. لو محددتش حاجة، الباكِت بيبقى على **Standard** (القياسي).

| **فئة التخزين**  | **الاسم في الأوامر** | **أقل مدة تخزين** | **رسوم استرجاع** | **التوفر الشهري**                           |
| :--------------- | :------------------- | :---------------- | :--------------- | :------------------------------------------ |
| Standard (قياسي) | `STANDARD`           | مفيش              | مفيش             | >99.99% (متعدد/مزدوج); 99.99% (منطقة واحدة) |
| Nearline (قريب)  | `NEARLINE`           | 30 يوم            | فيه              | 99.95% (متعدد/مزدوج); 99.9% (منطقة واحدة)   |
| Coldline (بارد)  | `COLDLINE`           | 90 يوم            | فيه              | 99.95% (متعدد/مزدوج); 99.9% (منطقة واحدة)   |
| Archive (أرشيف)  | `ARCHIVE`            | 365 يوم           | فيه              | 99.95% (متعدد/مزدوج); 99.9% (منطقة واحدة)   |

### Which class should you use?

| **فئة التخزين**      | **بتستخدمها إمتى؟**                                                                                         |
| :------------------- | :---------------------------------------------------------------------------------------------------------- |
| **Standard (قياسي)** | للداتا اللي بتتقرا كتير (Hot Data) أو اللي بتتخزن لفترة قصيرة.                                              |
| **Nearline (قريب)**  | للداتا اللي بتتقرا قليل (أقل من مرة في الشهر)، زي الباك أب والداتا اللي بترجعلها من وقت للتاني.             |
| **Coldline (بارد)**  | للداتا اللي نادراً ما تتقرا (أقل من مرة في الربع)، زي النسخ الاحتياطي على المدى الطويل والتعافي من الكوارث. |
| **Archive (أرشيف)**  | أرخص فئة للداتا اللي مش بتتقرا خالص (مرة في السنة)، زي أرشيفات الامتثال والسجلات القانونية.                 |

**Autoclass**: لو فعّلتها على الباكِت، جوجل هتحوّل الأوبجكتس بين الفئات لوحدها على حسب طريقة استخدامك.

## What it is made of

### Object storage

#### 1. Cloud Storage (GCS)

تخزين جوجل كلاود ده خدمة تخزين أوبجكت مُدارة وقابلة للتوسع، وبتوفر تخزين متين ومتاح عالمياً لأي نوع من شغل الشركات. بيتميز بـ:

- **تخزين ملوش آخر** مع وصول ملوش آخر.
- **مفيش حد أدنى لحجم الأوبجكت**.
- **متاح من أي حتة في العالم**.
- **زمن استجابة واطي** من غير ما تحتاج تحمّل الداتا الأول.
- **متانة 99.999999999% في السنة** (يعني 11 تسعة).
- **تكرار بين المناطق** لو خزنت في أكتر من منطقة.

الباكِتس بتتقسم لـ **منطقة واحدة (Single-Region)**، أو **منطقتين (Dual-Region)**، أو **متعددة المناطق (Multi-Region)**، وكل واحد ليه سعره وزمن استجابته.

#### 2. Cloud Storage for Firebase

دي في الأساس نفس تخزين جوجل كلاود، بس عليها طبقة من Firebase Authentication وSecurity Rules. بتخليك ترفع وتشارك محتوى المستخدمين زي الصور والفيديوهات بسهولة.

- الداتا بتتخزن في باكِت جوجل كلاود، وده بيوفر متانة عالية وتكرار عالمي.
- مكتبات العميل (Client SDKs) بتتعامل مع الرفع القابل للاستكمال، وتوليد روابط التحميل، ومتابعة التقدم.

### Block storage

تخزين البلوك بيقدّم الداتا على شكل بلوكات خام، ومصمم للأشغال اللي محتاجة أداء عالي وسرعة قراءة وكتابة.

#### 3. Persistent Disk

القرص الدائم ده الخيار الأساسي لتخزين البلوك في Compute Engine.

- **مش مؤقت** — الداتا بتفضل موجودة بعد ما الـ Pod أو الـ VM يخلصوا.
- بيدعم القراءة المشتركة (Read-Only) وشكل محدود من الكتابة المتعددة (Multi-Writer).

#### 4. Hyperdisk

الـ Hyperdisk ده أسرع وأكفأ قرص دائم في Compute Engine. بيخليك تدير وتوسّع أحمال شغلك من غير تعقيدات شبكات التخزين (SAN) المحلية.

بيستخدم تقنية **Titanium** من جوجل عشان يديك IOPS وThroughput أعلى من Persistent Disk.

**أنواع Hyperdisk:**

| **النوع**            | **السعة**      | **مُحسَّن لـ**                      |
| :------------------- | :------------- | :---------------------------------- |
| Hyperdisk Balanced   | 4 GiB – 64 TiB | أداء متوازن للأغراض العامة          |
| Hyperdisk Extreme    | بيختلف         | أداء عالي للأحمال الصعبة            |
| Hyperdisk Throughput | بيختلف         | الأحمال اللي محتاجة تمرير داتا عالي |

الـ Hyperdisk بيتوصل بالشبكة، يعني تقدر تفصله وتركبه على عقدة تانية والداتا تفضل موجودة.

#### 5. Local SSD

الـ Local SSD ده أقراص محلية بتتوصل بالـ instance.

- كل قرص بيوفّر **375 GiB**.
- أداء عالي أوي وزمن استجابة واطي أوي.
- مناسب للتخزين المؤقت (Scratch Space) والكاش والداتا المؤقتة.
- بيتوصل بـ **NVMe** أو **SCSI**.

### File storage

تخزين الملفات بيوفّر أنظمة ملفات مشتركة بتتوصل من خلال بروتوكولات الشبكة زي NFS وSMB.

#### 6. Filestore

Filestore دي سيرفرات ملفات مُدارة بالكامل في جوجل كلاود، وبتستخدم كتخزين دائم بوضع **ReadWriteMany** لعناقيد GKE.

- على عكس الـ Persistent Disk اللي بيسمح بوضع قراءة-كتابة واحد، الـ Filestore بتقدر توصلها من كذا عقدة في نفس الوقت.
- دي الخيار الأكثر استخداماً لما يكون فيه كذا Pod محتاجين يقرأوا ويكتبوا في نفس الفوليوم.

#### 7. Google Cloud NetApp Volumes

NetApp Volumes دي خدمة مُدارة في جوجل كلاود بتوفّر أنظمة ملفات مشتركة من نوع **NFS** و**SMB** للـ VM instances.

- بتوفّر إمكانيات إدارة داتا متقدمة وسعة وأداء عاليين.
- بتدعم تطبيقات الشركات وقواعد البيانات وأحمال الذكاء الاصطناعي من غير ما تعيد تبني حاجة.
- فيها مستوى خدمة **Flex Unified** بيدعم أحمال الملفات والبلوك من نفس المخزن في كل مناطق جوجل.

#### 8. Google Cloud Managed Lustre

Managed Lustre دي نظام ملفات متوازي (Parallel File System) عالي الأداء ومُدار بالكامل، ومُحسَّن لتطبيقات الذكاء الاصطناعي والحوسبة عالية الأداء (HPC). مبنية على DDN's EXAScaler Lustre وبتوفّر:

| **الميزة**    | **المواصفات**                                            |
| :------------ | :------------------------------------------------------- |
| Throughput    | لحد 10 TBps                                              |
| السعة         | لحد 1 PB (ولحد 38.2 PiB في فئات معينة)                   |
| IOPS          | لحد 5,800 قراءة/ثانية لكل TiB و5,600 كتابة/ثانية لكل TiB |
| زمن الاستجابة | أقل من مللي ثانية                                        |

Managed Lustre دي الحل الأساسي الموصى بيه لتدريب الذكاء الاصطناعي وعمل نقاط التفتيش (Checkpointing). وبتقدر توصلها بـ Compute Engine أو GKE.

#### 9. Parallelstore

Parallelstore دي نظام ملفات موزع وزمن استجابته واطي ومُدار بالكامل، ومصمم للحوسبة عالية الأداء (HPC) والتطبيقات اللي بتتعامل مع داتا ضخمة.

- مبنية على Intel DAOS.
- بتوفّر أداء قراءة أعلى بـ **6.3 مرة** من حلول Lustre Scratch المنافسة.
- السعة من **12 TiB لـ 100 TiB**.
- متوافقة مع POSIX.
- بتوفّر IOPS وThroughput عاليين أوي مع زمن استجابة واطي أوي.

## How it integrates with Google Cloud

تخزين جوجل كلاود بيتكامل مع خدمات كتير:

| **خدمة جوجل كلاود**       | **التكامل**                                                                     |
| :------------------------ | :------------------------------------------------------------------------------ |
| **AI Hypercomputer**      | تخزين داتا التدريب الضخمة لـ GPU/TPU، واستخدام Cloud Storage FUSE لأحمال AI/ML. |
| **App Engine**            | تخزين الأصول الثابتة (Static Assets).                                           |
| **BigQuery**              | الاستعلام والاستيراد والتصدير.                                                  |
| **Cloud Asset Inventory** | إدارة باكِتس التخزين والموارد التانية.                                          |
| **Cloud CDN**             | توصيل المحتوى للمستخدمين من أقرب نقطة عبر شبكة جوجل.                            |
| **Cloud Load Balancing**  | استخدام باكِتس التخزين كـ Backends لموازن التحميل.                              |
| **Cloud Logging**         | تخزين السجلات (Logs) في التخزين.                                                |
| **Cloud Run functions**   | عمل دوال بتشتغل لما يحصل حدث في التخزين.                                        |
| **Cloud SQL**             | استيراد وتصدير الداتا.                                                          |
| **Cloud Storage FUSE**    | تركيب باكِتس التخزين كأنها نظام ملفات محلي.                                     |
| **Compute Engine**        | استخدام التخزين من جوه الـ VM instances.                                        |
| **Config Connector**      | إدارة موارد جوجل كلاود بأدوات Kubernetes.                                       |

وكمان، تخزين جوجل كلاود هو الأساس لخدمات تانية زي **Google Prediction API** و**Google BigQuery Service**.

## Access control

تخزين جوجل كلاود بيستخدم **إدارة الهوية والوصول (IAM)** عشان يتحكم في الوصول للباكِتس والفولدرات المُدارة والأوبجكتس.

### Core concepts

- **أدوار IAM**: الصلاحيات بتتجمّع في أدوار، وبتتدي للمستخدمين والمجموعات. زي `roles/storage.admin` اللي بيدي تحكم كامل.
- **الوصول الموحد على مستوى الباكِت**: لو فعّلتها، سياسات IAM بتتطبق على كل الأوبجكتس في الباكِت، وده بيسهّل الإدارة.
- **الفولدرات المُدارة**: بتديك صلاحيات زيادة أو أقل من الصلاحيات اللي على الباكِت نفسه.
- **الوصول العام**: تقدر تدي صلاحيات تخلي الداتا متاحة لأي حد على الإنترنت.

## Pricing

الأسعار بتختلف على حسب فئة التخزين والمنطقة. الجدول ده فيه أسعار تقريبية شهرياً للمناطق الأمريكية. دايمًا راجع صفحة الأسعار الرسمية عشان تعرف الأسعار الحالية.

| **فئة التخزين** | **السعر التقريبي شهرياً (منطقة أمريكية)** | **أقل مدة تخزين** |
| :-------------- | :---------------------------------------- | :---------------- |
| Standard        | \~$0.020/GB-شهر                           | مفيش              |
| Nearline        | \~$0.010/GB-شهر                           | 30 يوم            |
| Coldline        | \~$0.004/GB-شهر                           | 90 يوم            |

**ملاحظات:**

- الباكِتس متعددة المناطق والمناطق المزدوجة ليها أسعار مختلفة.
- أسعار Hyperdisk وPersistent Disk بتختلف على حسب النوع والمنطقة.

## Choosing the right service

The easiest way to choose is to start with the storage interface your workload needs: object, block, or file.

💬شرح

| **نوع الشغل**                                        | **الخدمة الموصى بيها**                             |
| :--------------------------------------------------- | :------------------------------------------------- |
| داتا غير منظمة، أصول ثابتة، باك أب                   | Cloud Storage (Standard/Nearline/Coldline/Archive) |
| محتوى مستخدمين لتطبيقات الموبايل                     | Cloud Storage for Firebase                         |
| أقراص إقلاع VM، قواعد بيانات، تخزين بلوك عام         | Persistent Disk                                    |
| تخزين بلوك عالي الأداء لأحمال صعبة                   | Hyperdisk                                          |
| مساحة مؤقتة عالية السرعة                             | Local SSD                                          |
| نظام ملفات مشترك لـ GKE (ReadWriteMany)              | Filestore                                          |
| تخزين ملفات للشركات (NFS/SMB) لـ SAP وقواعد البيانات | NetApp Volumes                                     |
| تدريب AI/ML وأحمال HPC المتوازية                     | Managed Lustre                                     |
| تطبيقات HPC وزمن استجابة واطي                        | Parallelstore                                      |

### Quick decision guide

- **تخزين الأوبجكت**: Cloud Storage، وCloud Storage for Firebase.
- **تخزين البلوك**: Persistent Disk، وHyperdisk، وLocal SSD.
- **تخزين الملفات**: Filestore، وNetApp Volumes، وManaged Lustre، وParallelstore.

تخزين جوجل كلاود هو الخيار الموصى بيه لتخزين الأوبجكت. والـ Persistent Disk والـ Hyperdisk بيخدموا احتياجات تخزين البلوك. أما Filestore وNetApp Volumes وManaged Lustre وParallelstore فبيغطوا تخزين الملفات. والـ Local SSD بيوفّر تخزين عالي الأداء بس مؤقت.
